# GRE-TUN 12.3.0 — راه‌اندازی خودکار Transparent

## فقط همین اسکریپت را روی هر سرور اجرا کن

فایل ZIP را **کامل** روی خارج و هر ایران استخراج کن. داخل پوشه بسته:

```bash
sudo bash transparent-auto.sh
```

این ورودی پیش‌نیازهای ناقص را نصب می‌کند، فایل‌های مدیر و ماژول را محلی نصب می‌کند و راه‌اندازی خودکار را باز می‌کند. نیازی به دستورهای جدا برای iptables، route، WireGuard، ساخت plan یا کپی token نیست.

بعد از نصب، بدون نیاز به برگشت به پوشه ZIP:

```bash
sudo bash /usr/local/bin/gretun-manager.sh --transparent
```

از منوی عادی هم مسیر **۶ — HAProxy → ۹ — automatic transparent IP** همین راه‌اندازی را باز می‌کند.

## ترتیب اجرا

### اول خارج

1. گزینه **۲ — Outside** را بزن.
2. اینترفیس‌های GRE، GRE Plus و WireGuard فعال، آدرس داخلی و peer خودکار پیدا می‌شوند؛ اسم و IP آن‌ها را وارد نمی‌کنی.
3. پورت TCP مقصد را انتخاب کن. پورت‌های Xray به‌صورت پیش‌فرض پیشنهاد می‌شوند؛ برای شروع می‌توانی `2044` را وارد کنی. چند پورت مثل `2044,11111` هم قبول می‌شود. `0` همه پورت‌های فهرست را انتخاب می‌کند؛ همه را فقط وقتی انتخاب کن که واقعاً قصد آماده‌سازی همه آن‌ها را داری.
4. فهرست مسیرها را ببین و Enter بزن. اسکریپت روی هر اینترفیس مناسب، مسیر برگشت مستقل را آماده می‌کند.
5. وقتی پیام **Outside ready** آمد، برو روی ایران‌ها. سرویس بررسی آمادگی در خارج خودکار فعال می‌شود و token لازم نیست.

### بعد هر ایران

1. همان اسکریپت را اجرا و گزینه **۱ — Iran** را انتخاب کن.
2. فورواردهای فعلی TCP از HAProxy خوانده می‌شوند. پورت عمومی موردنظر را انتخاب کن؛ اگر موجود باشد `2044` پیش‌فرض است.
3. اسکریپت از روی مقصد همان فوروارد و مسیر واقعی کرنل تشخیص می‌دهد کدام GRE/GRE Plus/WireGuard باید استفاده شود. هیچ شماره تونل یا IP دستی لازم نیست.
4. Enter بزن. آمادگی خارج از داخل همان تونل بررسی می‌شود. اگر خارج آماده نباشد، تنظیم HAProxy ایران تغییر نمی‌کند.
5. اگر آماده باشد، listener آزمایشی و تنظیمات شبکه به‌صورت خودکار ساخته می‌شوند. **پورت آزمایشی چاپ‌شده را یادداشت کن**؛ معمولاً برای 2044 برابر 12044 است، ولی اگر مشغول باشد پورت آزاد دیگری انتخاب می‌شود.
6. یک کپی از کانفیگ یک کلاینت را با همان مشخصات و فقط پورت آزمایشی امتحان کن. بازشدن سایت، handshake و نمایش IP واقعی در خارج را تأیید کن.
7. از همین راه‌اندازی گزینه **۳ — Activate tested Iran trials** را بزن؛ ردیف آزمایش موفق را انتخاب کن و `ACTIVATE` بنویس. اسکریپت دوباره آمادگی خارج را بررسی و فوروارد اصلی را با reload منتقل می‌کند.

نصب و تنظیمات سیستم خودکارند؛ آزمون واقعی کلاینت همچنان لازم است، چون اسکریپت رمز/UUID یا مشخصات کلاینت کاربر را برای احراز هویت در اختیار ندارد. قبل از این مرحله فوروارد اصلی به‌طور خودکار به حالت جدید منتقل نمی‌شود.

## برای سه سرور فعلی شما

روی خارج، دو مسیر فعلی و هر GRE فعال دیگر به‌صورت خودکار دیده می‌شوند. روی ایران اول مقصد `10.20.1.2` به `wgtun1` نگاشت می‌شود؛ روی ایران دوم مقصد `10.30.3.2` به `greplus3` نگاشت می‌شود. این اعداد نمونه وضعیت فعلی شما هستند؛ **در منطق راه‌اندازی خودکار ثابت نشده‌اند**.

اگر بعداً `gre7`، `greplus12`، `wgtun8` یا یک نام متفاوت برای GRE/WireGuard اضافه شود، نوع رابط از اطلاعات کرنل شناسایی می‌شود. لازم نیست اسکریپت را برای شماره‌های جدید ویرایش کنی.

## چه چیزهایی خودکار انجام می‌شوند؟

- نصب پیش‌نیازهای ناقص و نصب محلی مدیر؛ بدون ارتقای کلی سیستم یا ریبوت.
- تشخیص نوع اینترفیس از `ip -j`، نه فهرست ثابت نام‌ها.
- یافتن peer یکتا از آدرس point-to-point، شبکه /30 یا /31، peer WireGuard یا host-route یکتا. رابط مبهم حدس زده نمی‌شود.
- شناسایی فورواردهای موجود در ایران و listenerهای مقصد در خارج، شامل listenerهای dual-stack Xray؛ پذیرش واقعی اتصال IPv4 هم بررسی می‌شود.
- ساخت و اعمال مسیر برگشت مستقل هر ایران، فایروال محدود به مسیر و پورت، تنظیمات سازگار WireGuard و پایداری بعد از شروع دوباره رابط.
- انتخاب پورت آزمایشی آزاد، ایجاد listener، بررسی آمادگی سمت مقابل و خلاصه موارد موفق/ناموفق.
- اجرای مجدد بدون ساخت پروفایل تکراری و بدون restart کردن HAProxy برای تعمیر تنظیمات شبکه.
- فعال‌سازی بعد از آزمایش و برگشت تدریجی از داخل همین منو.

## وضعیت و برگشت

گزینه **۴ — Status** وضعیت پروفایل‌ها را نشان می‌دهد.

گزینه **۵ — Drain / cleanup** ردیف موردنظر را می‌گیرد. بار اول اتصال‌های جدید را به مسیر قبلی برمی‌گرداند؛ مسیر اتصال‌های باز باقی می‌ماند. بعد از اتمام اتصال‌ها، با انتخاب دوباره همان ردیف پاک‌سازی انجام می‌شود. ابتدا ایران را drain/cleanup کن، سپس همان مسیر را در خارج. هیچ flush عمومی conntrack یا تغییر default gateway انجام نمی‌شود.

گزینه **۶ — Advanced** ابزارهای دستی نسخه قبل را نگه داشته است، ولی برای روال عادی نیازی به آن یا token نداری.

## بررسی آمادگی خودکار خارج

یک پاسخ‌دهنده فقط‌خواندنی روی TCP `45123` اجرا می‌شود. در سطح برنامه تنها وقتی پاسخ می‌دهد که آدرس مقصد همان IP داخلی خارج و IP مبدأ همان peer داخلی ایران ثبت‌شده باشد. درخواست نمی‌تواند تنظیم سرور را عوض کند یا کلید/رمز بخواند. قوانین فایروال هم به همین رابط و دو آدرس محدودند. ایران، وجود قوانین برگشت و مسیر صحیح و دسترس‌پذیری TCP مقصد را بررسی می‌کند؛ این آزمون جای handshake واقعی کلاینت را نمی‌گیرد.

اگر 45123 متعلق به برنامه دیگری باشد، آن برنامه متوقف نمی‌شود؛ راه‌اندازی آمادگی با خطا متوقف خواهد شد. پس از حذف آخرین پروفایل خارج، پاسخ‌دهنده اختصاصی این قابلیت نیز بسته می‌شود.

## محدودیت‌های روشن

- این نسخه برای **IPv4، HAProxy mode tcp و GRE/GRE Plus/WireGuard** است. mode http مثل 2095/8080 فعلی، IPv6، TLS termination در خود HAProxy و BackPack Transparent خودکار فعال نمی‌شوند. تونل و فوروارد عادی BackPack همچنان داخل بسته موجود است.
- WireGuard خارج باید یک peer و تنظیم پایه ساده داشته باشد. پذیرش IP واقعی به گسترش AllowedIPs همان peer به 0.0.0.0/0 نیاز دارد؛ Table=off مانع ساخت default route عمومی می‌شود. کلیدها و Endpoint عوض نمی‌شوند. برای آدرس /32، مسیر host همان peer در شروع دوباره حفظ می‌شود.
- WireGuard چند peer، AllowedIPs سفارشی، hookهای دستی و SaveConfig خودکار برای بازبینی متوقف می‌شوند.
- CAP_NET_ADMIN و روی ایران CAP_NET_RAW، systemd و HAProxy دارای TPROXY با graceful reload لازم‌اند. سرویس سخت‌سازی‌شده یا تداخل جدول/mark حدس زده نمی‌شود و اسکریپت برای دورزدن محدودیت‌ها کاربر سرویس را عوض نمی‌کند.
- peer مبهم، اینترفیس DOWN، route فیزیکی به‌جای تونل، پورت اشغال یا خارج آماده‌نشده با دلیل رد می‌شوند؛ موفقیت ساخت یک مسیر به معنی موفقیت همه مسیرها اعلام نمی‌شود.
- در Ubuntu 22.04/24.04 مسیر نصب پیش‌نیازها آماده است. fallback نصب DNF هم وجود دارد، ولی فعال‌سازی روی همه توزیع‌ها و همه تنظیمات دلخواه تضمین نشده است.
- تا وقتی پروفایل فعال است، مدیر از بازسازی تنظیمات محافظت‌شده جلوگیری می‌کند. تغییر دستی توسط ابزارهای دیگر خارج از این حفاظت است.

## اعتبارسنجی

```bash
python3 -m unittest discover -s tests -v
bash -n GRETUN.sh
bash -n transparent-auto.sh
sha256sum -c DISTRIBUTION-SHA256SUMS
```

۷۰ تست خودکار موفق است؛ از جمله تشخیص نام‌های دلخواه، هر سه نوع تونل، /30 و /31 و peer /32، عدم نیاز به token، عدم تغییر ایران هنگام آماده‌نبودن خارج، حفظ پروفایل در اجرای تکراری و تبادل واقعی پیام آمادگی روی loopback. واحدهای systemd مربوط به restore، readiness و WireGuard بررسی شده‌اند. عبور واقعی ترافیک GRE/WireGuard و handshake کاربران در سرورهای شما در این محیط آزمایش نشده است.

مستندات دقیق روش پایه و ابزارهای پیشرفته در `docs/README-v12.2.0-manual.md` و نتیجه آزمون جدید در `docs/auto-test-results.txt` قرار دارد. فایل‌های موتور و مجوزهای BackPack کامل نگه داشته شده‌اند.
