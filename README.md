# GRE-TUN v12.0.4

مدیریت GRE، GRE Plus، WireGuard و HAProxy.

## اجرای نسخه داخل ZIP

فایل‌ها را استخراج کنید و در پوشه پروژه اجرا کنید:

```bash
sudo bash GRETUN.sh
```

روی هر دو سرور این نسخه را اجرا کنید. برای دریافت همین نسخه، فایل محلی داخل بسته را اجرا کنید؛ دستور GitHub تا زمانی که فایل مخزن جایگزین نشده، نسخه مخزن را می‌گیرد. این بسته مخزن GitHub را تغییر نمی‌دهد.

## راه‌اندازی مجدد شماره ۳ روی GRE Plus

1. منوی ایجاد/ویرایش تونل را باز کنید و WireGuard را انتخاب کنید.
2. روی سرور ایران نقش ایران و روی سرور خارج نقش خارج را انتخاب کنید؛ شماره هر دو `3` باشد.
3. اگر GRE و GRE Plus هر دو فعال‌اند، روی **هر دو سرور گزینه ۲، GRE Plus** را انتخاب کنید.
4. کلید عمومی سرور مقابل را وارد کنید؛ اگر کلید درست از قبل ذخیره شده است، با Enter نگه دارید.
5. پورت REMOTE باید برابر ListenPort نمایش‌داده‌شده در سرور مقابل باشد. پیش‌فرض شماره ۳ برابر `51803` است، ولی اگر پورت محلی اشغال باشد مقدار آزاد دیگری انتخاب می‌شود. پورت‌های محلی دو سرور لازم نیست برابر باشند.
6. در منوی تست، WireGuard شماره ۳ را انتخاب کنید.

اگر کلید طرف مقابل را ندارید، Enter آن را با وضعیت `pending-key` ذخیره می‌کند. اتصال تا ورود کلید عمومی صحیح در هر دو طرف برقرار نمی‌شود.

مقادیر انتظار روی ایران:

- اینترفیس انتقال: `greplus3`
- Endpoint: `10.30.3.2:<ListenPort سرور خارج>`
- IP وایرگارد: `10.20.3.1/30`

روی خارج، Endpoint برابر `10.30.3.1:<ListenPort سرور ایران>` و IP وایرگارد برابر `10.20.3.2/30` است.

اگر تنظیمات ذخیره‌شده صحیح است و فقط سرویس غیرفعال شده، انتخاب وایرگارد در منوی تست، کانفیگ و سرویس آن را از اطلاعات ذخیره‌شده بازسازی می‌کند. اگر کلید ذخیره نشده باشد، علت را صریح نشان می‌دهد.

## تغییرات 12.0.4

- اصلاح تشخیص اشغال بودن UDP در خروجی `ss`؛ ستون Peer دیگر به‌جای Local بررسی نمی‌شود.
- نگه‌داشتن پورت وایرگارد فعلی هنگام ویرایش، با تشخیص مالکیت همان اینترفیس.
- ذخیره و ورود مستقل پورت سرور مقابل؛ برابر فرض‌کردن آن با پورت محلی حذف شد.
- جلوگیری از انتشار تنظیمات یک تونل به دیگری در بررسی وابستگی، فایروال و ساخت فهرست.
- انتظار محدود برای آماده‌شدن GRE/GRE Plus و ثابت‌کردن مسیر آدرس داخلی Endpoint روی اینترفیس انتخاب‌شده.
- راه‌اندازی سرویس وایرگارد با مرحله آماده‌سازی مسیر و فایروال، و بررسی وجود اینترفیس پس از شروع سرویس.
- انتقال خطاهای ساخت به منو؛ خروج موفق `systemctl` به‌تنهایی موفقیت تونل تلقی نمی‌شود.
- نمایش وضعیت سرویس و آخرین لاگ‌ها هنگام شکست شروع وایرگارد.
- بازسازی کانفیگ و override سرویس در تعمیر، بدون تغییر کلید خصوصی معتبر.
- بازگرداندن کانفیگ و متادیتای قبلی در صورت شکست ویرایش و تلاش برای بازگرداندن تونل قبلی، اگر فعال بوده است.
- حفظ وایرگارد فعلی هنگام انصراف از ورود کلید یا انتخاب مسیر.
- تولید کلید با کنترل خطا و بازسازی کلید عمومی از همان کلید خصوصی؛ کلید خصوصی نامعتبر بدون اطلاع حذف یا عوض نمی‌شود.
- نوشتن اتمیک فایل‌های تنظیمات GRE، GRE Plus و WireGuard.
- توقف تعمیر خودکار supervisorها هنگام ایجاد/حذف/reset دستی و توقف سرویس GRE پیش از reset.
- حفظ قانون فایروال مشترک هنگام حذف یک GRE Plus از میان چند تونل با همان دو IP عمومی.
- بررسی handshake وایرگارد وابسته در سلامت GRE Plus و راه‌اندازی دوباره وابستگان پس از تعمیر واقعی اینترفیس.
- نمایش `pending-key` به‌جای `inactive` در فهرست وقتی کلید سرور مقابل وارد نشده است.
- گزارش خطا در reset کلی به‌جای نمایش موفقیت وقتی یک تونل شکست خورده است.

تنظیمات جلوگیری از ریست به‌خاطر افت موقت پینگ حفظ شده است. قابلیت یا ظاهر جدیدی برای HAProxy اضافه نشده است.

## بررسی‌ها و محدودیت

```bash
bash -n GRETUN.sh
python3 -m unittest discover -s tests -v
```

۲۹ تست خودکار، بررسی نحو Bash و اعتبارسنجی واحدهای systemd موفق بود. تست‌ها شامل حالت‌های انتخاب، دو نقش، سناریوی شماره ۳، ذخیره تنظیمات، خطاهای شروع، اشغال پورت، انصراف، MTU، قوانین فایروال، وابستگی، بازگردانی و تعمیر هستند. شش ایراد ابتدا با تست شکست روی نسخه قبلی بازتولید شد.

شبکه و سرویس‌ها در تست‌های خودکار شبیه‌سازی شده‌اند. در این محیط مجوز ایجاد اینترفیس شبکه یا دسترسی به سرورهای شما وجود ندارد؛ handshake و عبور ترافیک واقعی بین دو سرور آزمایش نشده است. جدول `inactive` به‌تنهایی علت دقیق شکست شروع سرویس در سرور شما را مشخص نمی‌کند.

## دریافت خطای واقعی شماره ۳

اگر پس از اجرای نسخه جدید همچنان غیرفعال بود، خروجی این دو دستور روی هر دو سرور علت سرویس را مشخص می‌کند:

```bash
sudo systemctl status wg-quick@wgtun3.service --no-pager -l
sudo journalctl -u wg-quick@wgtun3.service -n 40 --no-pager
```

برای بررسی انتقال و handshake:

```bash
ip -br addr show greplus3
ip -4 route get 10.30.3.2
sudo wg show wgtun3
```

دستور route بالا برای سمت ایران است؛ در سرور خارج مقصد را `10.30.3.1` قرار دهید. خروجی کانفیگ کامل یا کلید خصوصی را ارسال نکنید.
