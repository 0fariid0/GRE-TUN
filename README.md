# GRE-TUN 12.5.5 — اصلاح حذف، نصب و گزارش خطا

## نصب قطعی همین نسخه

ZIP را کامل استخراج کن و داخل پوشه اجرا کن:

```bash
sudo bash install-local.sh
bash /usr/local/bin/gretun-manager.sh --version
sudo bash /usr/local/bin/gretun-manager.sh
```

دستور نسخه باید `12.5.5` نشان بدهد. نصب نسخه جدید خودش تونل‌ها را ریست نمی‌کند. اگر از دستور curl قبلی استفاده می‌کنی، باید فایل‌های همین بسته را در مخزن جایگزین کرده باشی؛ بسته خودش GitHub را تغییر نمی‌دهد. نصب سرویس دیگر فایل با نسخه متفاوت را به‌جای نسخه در حال اجرا قبول نمی‌کند و خطای نسخه را قبل از بازسازی GRE/ویرایش/ریست نشان می‌دهد.

## حذف

منوی اصلی **۲ — remove tunnel**، ردیف یا ردیف‌ها را انتخاب کن؛ `88` همه تونل‌ها شامل BackPack را انتخاب می‌کند. شماره ردیف با ID تونل فرق دارد. اگر WireGuard از GRE/GRE Plus استفاده می‌کند، ردیف WireGuard را هم همراه والد انتخاب کن؛ ابتدا فرزند حذف می‌شود. اگر حذف WireGuard شکست بخورد، حذف والد وابسته متوقف می‌شود.

پروفایل Transparent همان رابط خودکار به حالت معمولی برمی‌گردد و قوانین/مسیرهای اختصاصی آن پاک می‌شوند. حذف تونل به معنی قطع اتصال‌های همان تونل است؛ فقط conntrack با mark اختصاصی آن پروفایل حذف می‌شود، نه flush عمومی و نه پروفایل رابط دیگر. اگر سرویس متوقف نشود یا رابط همچنان وجود داشته باشد، کانفیگ حذف نمی‌شود و پیام موفقیت نشان داده نمی‌شود. فایل‌های اختصاصی GRE-TUN از drop-in وایرگارد حذف می‌شوند؛ drop-in سفارشی دیگر پاک نمی‌شود.

حذف/ریست به سرور مقابل فرمان نمی‌فرستد. قواعد فوروارد معمولی HAProxy با حذف تونل به‌طور خودکار حذف نمی‌شوند؛ برای استفاده از مقصد جدید، فوروارد مربوط را خودت به مقصد مناسب تغییر بده.

## ساخت / ویرایش / ریست

ساخت شماره جدید مسیر قبلی را دارد. برای ویرایش GRE/GRE Plus، گزینه ۱ و همان نوع و شماره را انتخاب کن؛ Enter هر IP را حفظ می‌کند و تغییر IP همان مقدار را عوض می‌کند. نقش و آدرس داخلی تونل موجود ثابت می‌مانند. خرابی نصب سرویس GRE اکنون خطا گزارش می‌شود، نه موفقیت کاذب؛ ویرایش تلاش می‌کند فایل و رابط قدیمی را برگرداند.

گزینه ۳ کانفیگ‌ها و نصب مدیر را قبل از توقف بررسی می‌کند. WireGuard با فایل ذخیره‌شده راه‌اندازی می‌شود؛ کلیدها و AllowedIPs دوباره ساخته نمی‌شوند. GRE/Plus قبل از WG بالا می‌آیند و Transparent پس از آن restore می‌شود. ریست اتصال‌های کاربران را قطع‌و‌وصل می‌کند.

## بررسی انجام‌شده و محدودیت

۱۳۲ تست خودکار گذشته‌اند. نصب محلی با خود اسکریپت در مسیر جدا اجرا و بایت‌های مدیر/ماژول نصب‌شده با بسته مقایسه شده‌اند. دریافت نسخه درست/غلط از pipe، حذف جزئی/همه، نگهداری فایل در خطا، وابستگی WG، ویرایش IP، ریست و Transparent تست شده‌اند. عملیات کرنل در تست‌ها مدل‌سازی شده‌اند؛ این محیط CAP_NET_ADMIN ندارد و ساخت/حذف واقعی رابط یا اتصال کاربران روی سرور شما آزمایش نشده است. این گزارش ادعای رفع همه اشکالات احتمالی پروژه نیست.

راهنماهای زیر تاریخی هستند؛ برای نسخه فعلی موارد بالا ملاک است.

# ویرایش IP همان شماره GRE — نسخه 12.5.4

از منوی اصلی **۱ — create/update tunnel**، نوع **GRE معمولی یا GRE Plus** و شماره قبلی را انتخاب کن. اطلاعات ذخیره‌شده به همراه IP ایران و خارج نشان داده می‌شوند. در دو سؤال LOCAL و REMOTE، Enter مقدار قبلی را حفظ می‌کند و واردکردن IP جدید همان مقدار را تغییر می‌دهد. `00` قبل از اعمال برمی‌گردد و چیزی تغییر نمی‌کند. اگر هر دو مقدار حفظ شوند، تونل دست‌نخورده می‌ماند و ریست نمی‌شود.

LOCAL یعنی IP همین سروری که اسکریپت روی آن اجرا شده؛ REMOTE یعنی IP سرور مقابل. نقش سرور، شماره تونل و آدرس‌های داخلی از کانفیگ ذخیره‌شده حفظ می‌شوند. انتخاب نقش در مرحله اول برای تونل موجود، نقش ذخیره‌شده را عوض نمی‌کند. برای شماره جدید، مسیر ساخت قبلی اجرا می‌شود.

پروفایل Transparent مربوط به همان رابط پیش از تغییر بررسی و مسیرهای آن بعد از تغییر بازگردانی می‌شوند. محافظ حذف/تغییرات دیگر خاموش نشده است. اگر ساخت رابط جدید شکست بخورد، کانفیگ قبلی برگردانده و تلاش برای بازیابی رابط قبلی انجام می‌شود. تغییر IP ممکن است اتصال کاربران همان تونل را قطع کند. تغییر IP عمومی روی سرور مقابل هم باید در REMOTE این سمت اعمال شود؛ اسکریپت روی سرور دیگر SSH نمی‌زند.

این اصلاح ویرایش سریع IP برای GRE و GRE Plus است؛ مسیر ساخت/ویرایش WireGuard در این نسخه تغییر نکرده است.

نصب: ZIP را استخراج و داخل پوشه `sudo bash install-local.sh` را اجرا کن. پس از آن منوی اصلی گزینه ۱. برای curl، فایل‌های نسخه جدید را با هم در مخزن منتشر کن؛ این بسته خودش GitHub را تغییر نمی‌دهد.

۱۱۹ تست خودکار گذشته‌اند؛ ساخت و ویرایش واقعی روی سرورهای شما آزمایش نشده است.

# اصلاح گزینه ۳ در نسخه 12.5.3

گزینه ۳ منوی اصلی تونل‌های ذخیره‌شده را ریست می‌کند. محافظ Transparent دیگر ریست را به‌طور کلی مسدود نمی‌کند؛ به‌جای آن پروفایل‌ها و فایل‌های ذخیره‌شده قبل از توقف بررسی می‌شوند. تراکنش ناقص Transparent یا فایل WireGuard تغییریافته، قبل از قطع تونل خطا می‌دهد.

WireGuard از همان فایل ذخیره‌شده restart می‌شود؛ کلیدها، AllowedIPs و Table=off دوباره تولید نمی‌شوند. GRE/GRE Plus قبل از WireGuard بالا می‌آیند. مسیرهای Transparent در پایان مجدداً اعمال می‌شوند و خطای آن‌ها در نتیجه عملیات حساب می‌شود. ریست، حذف تونل یا پاک‌کردن پروفایل Transparent نیست.

برای نصب، بسته را استخراج و داخل پوشه `sudo bash install-local.sh` اجرا کن؛ سپس منوی اصلی گزینه ۳. ریست عمداً تونل‌ها را قطع و دوباره وصل می‌کند و ممکن است اتصال کاربران قطع شود. برای سرورهای دو سمت، نسخه یکسان را نصب کن و ریست را جداگانه روی هر سرور انجام بده.

۱۱۱ تست گذشته‌اند؛ شامل ترتیب اجرای ریست، نگهداری فایل WG، جلوگیری از توقف هنگام خرابی کانفیگ، تشخیص شکست restore و رد تراکنش ناقص. آزمون ریست واقعی روی سرورهای شما انجام نشده است.

# GRE-TUN 12.5.3 — روشن/خاموش روی پورت اصلی

در منوی اصلی **۹ — Transparent client IP** را انتخاب کن. منوی این بخش فقط سه گزینه دارد:

- **۱ — ON**: نقش ایران یا خارج و پورت‌ها را انتخاب کن؛ همان پورت اصلی فعال می‌شود.
- **۲ — OFF**: نقش و پورت‌ها را انتخاب کن؛ فوروارد معمولی برمی‌گردد.
- **00 — Back**: برگشت.

پورت آزمایشی جدیدی ساخته نمی‌شود و گزینه Activate لازم نیست. پورت‌ها با فاصله یا ویرگول مثل `2044 1030` یا `2044,1030,` قابل انتخاب‌اند؛ `0` همه پورت‌های فهرست را انتخاب می‌کند. رابط GRE، GRE Plus یا WireGuard خودکار از روی تنظیمات واقعی شناسایی می‌شود.

وضعیت پورت‌ها هنگام بازشدن منو و پس از هر عملیات به‌صورت خودکار نمایش داده می‌شود: `ON` روشن ایران، `OFF / normal forward` فوروارد معمولی، `READY (outside)` مسیر برگشت آماده در خارج، `OFF / draining` خاموش برای اتصال جدید با حفظ مسیر اتصال‌های قبلی، و `MISMATCH` ناسازگاری کانفیگ. روی خارج، وضعیت هر پورت و اینترفیس جداست. این جدول وضعیت همین سرور است، نه تأیید اتصال واقعی کلاینت یا وضعیت سرور دیگر.

## نصب / ارتقا

روی خارج و هر ایران، ZIP را کامل استخراج کن و داخل پوشه آن اجرا کن:

```bash
sudo bash transparent-auto.sh
```

این دستور پیش‌نیازهای ناقص و نسخه جدید مدیر را نصب و منوی روشن/خاموش را باز می‌کند. برای اجرای دفعات بعد:

```bash
sudo bash /usr/local/bin/gretun-manager.sh --transparent
```

**ابتدا روی خارج ON را اجرا کن؛ سپس روی ایران ON را برای پورت موردنظر بزن.** در ایران مقصد همان فوروارد فعلی HAProxy استفاده می‌شود. برای خاموش‌کردن **اول ایران‌ها، سپس خارج** را OFF کن. تأیید متنی یا Enter اضافه پرسیده نمی‌شود؛ این اسکریپت به سرور دیگر SSH نمی‌زند.

اگر OFF پیام draining داد، اتصال‌های قدیمی هنوز بازند؛ مسیر برگشت آن‌ها حفظ می‌شود. بعد از پایان آن‌ها، OFF را دوباره اجرا کن تا منابع باقی‌مانده پاک شوند. روشن‌کردن دوباره همان پورت در زمان draining پشتیبانی می‌شود.

## همان دستور curl قبلی

فایل‌های این بسته، به‌خصوص `GRETUN.sh` و `transparent_forward.py` را با هم در ریشه مخزن GitHub جایگزین کن. این بسته خودش مخزن را منتشر یا تغییر نمی‌دهد. بعد از انتشار، دستور همیشگی نسخه جدید را دریافت می‌کند:

```bash
bash <(curl -Ls --ipv4 https://raw.githubusercontent.com/0fariid0/GRE-TUN/refs/heads/main/GRETUN.sh)
```

گزینه ۹ منوی اصلی، فایل کمکی را خودکار دریافت می‌کند؛ SHA256 آن باید با همین نسخه مدیر تطبیق داشته باشد. دانلود ناموفق یا فایل ناسازگار جایگزین فایل قبلی نمی‌شود. ورودی مستقیم منوی اصلی روی خارج به نصب HAProxy نیاز ندارد.

## اصلاح 12.5.3

در ایران، accept_local فقط روی اینترفیس تونل فعال و مقدار قبلی قبل از تغییر ثبت می‌شود. این اصلاح تداخل src_valid_mark سراسری با جدول local مورد استفاده Transparent را پوشش می‌دهد. مقدار قبلی هنگام پاک‌سازی آخرین پروفایل همان رابط یا rollback نصب ناموفق برگردانده می‌شود؛ هنگام draining برای اتصال‌های باز باقی می‌ماند. تنظیمات all/default تغییر نمی‌کنند. پروفایل‌های نسخه قدیمی نیز هنگام ON/restore مقدار قبلی را ذخیره می‌کنند. تست TCP پیش از جابه‌جایی پورت اصلی همچنان اجباری است.

این اصلاح از روی capture رفت‌وبرگشت SYN/SYN-ACK، شمارنده socket mark و تنظیمات واقعی گزارش‌شده ایران تهیه شده است. موفقیت روی سرور واقعی هنوز باید با ON و اتصال کلاینت تأیید شود.

## تغییرات این نسخه

- روشن‌کردن روی پورت اصلی، بدون listener آزمایشی و بدون تغییر پورت کلاینت.
- اتصال backend شفاف HAProxy به رابط تونل انتخاب‌شده مقید می‌شود.
- قبل از جابه‌جایی فوروارد اصلی، اتصال TCP با source غیرمحلی روی همان رابط بررسی می‌شود؛ پاسخ `ready` و پینگ به‌تنهایی کافی نیستند.
- شکست این بررسی، فوروارد اصلی را جابه‌جا نمی‌کند. شکست reload نیز تلاش برای برگشت تنظیمات قبلی را اجرا می‌کند.
- تبدیل پروفایل‌های آزمایشی/فعال نسخه قبلی به حالت جدید، بدون listener اضافه؛ پشتیبانی از OFF و ON مجدد در حالت draining.
- سرویس آمادگی خارج باید واقعاً شروع به listen کند تا آماده گزارش شود؛ خطاهای بررسی در journal ثبت می‌شوند.
- گزارش خطای اعمال تنظیمات در `/etc/gretun-transparent/last-error.log` ذخیره می‌شود؛ شامل مسیرها و قوانین مربوط است و کلید WireGuard یا محتوای بسته‌های کاربران را ذخیره نمی‌کند.

## محدوده و نتیجه تست

این بخش برای **IPv4، فوروارد ساده TCP در HAProxy و رابط‌های routed GRE/GRE Plus و WireGuard تک-peer** است. HTTP/UDP، تنظیمات پیچیده HAProxy و WireGuard چند-peer خودکار تبدیل نمی‌شوند. در خارج، AllowedIPs همان peer WireGuard با Table=off برای دریافت source کاربران گسترش می‌یابد؛ جدول اصلی مسیریابی به default روی WireGuard تبدیل نمی‌شود.

۱۰۴ تست خودکار گذشته‌اند. آزمون‌ها شامل مدل‌سازی قوانین و چرخه rollback، نصب و بررسی واقعی loopback سرویس آمادگی هستند. این محیط CAP_NET_ADMIN ندارد؛ آزمون واقعی GRE/WireGuard و handshake کلاینت Xray روی سرورهای شما انجام نشده است. بررسی TCP جدید جای احراز هویت یا handshake برنامه را نمی‌گیرد. علت دقیق قطع قبلی از خروجی بعد از OFF قابل تعیین نبود؛ تضمین بی‌خطا بودن روی همه سرورها داده نمی‌شود.
