# GRE-TUN 12.5.1 — روشن/خاموش روی پورت اصلی

در منوی اصلی **۹ — Transparent client IP** را انتخاب کن. منوی این بخش فقط سه گزینه دارد:

- **۱ — ON**: نقش ایران یا خارج و پورت‌ها را انتخاب کن؛ همان پورت اصلی فعال می‌شود.
- **۲ — OFF**: نقش و پورت‌ها را انتخاب کن؛ فوروارد معمولی برمی‌گردد.
- **00 — Back**: برگشت.

پورت آزمایشی جدیدی ساخته نمی‌شود و گزینه Activate لازم نیست. پورت‌ها با فاصله یا ویرگول مثل `2044 1030` یا `2044,1030,` قابل انتخاب‌اند؛ `0` همه پورت‌های فهرست را انتخاب می‌کند. رابط GRE، GRE Plus یا WireGuard خودکار از روی تنظیمات واقعی شناسایی می‌شود.

وضعیت پورت‌ها هنگام بازشدن منو و پس از هر عملیات به‌صورت خودکار نمایش داده می‌شود: `ON` روشن ایران، `OFF / normal forward` فوروارد معمولی، `READY (outside)` مسیر برگشت آماده در خارج، `OFF / draining` خاموش برای اتصال جدید با حفظ مسیر اتصال‌های قبلی، و `MISMATCH` ناسازگاری کانفیگ. روی خارج، وضعیت هر پورت و اینترفیس جداست. این جدول وضعیت همین سرور است، نه تأیید اتصال واقعی کلاینت یا وضعیت سرور دیگر.

## نصب / ارتقا

روی خارج و هر ایران، ZIP را کامل استخراج کن و داخل پوشه آن اجرا کن:

```bash
sudo bash transparent-auto.sh
```

این دستور پیش‌نیازهای ناقص و نسخه جدید مدیر را نصب و منوی روشن/خاموش را باز می‌کند. برای اجرای دفعات بعد:

```bash
sudo bash /usr/local/bin/gretun-manager.sh --transparent
```

**ابتدا روی خارج ON را اجرا کن؛ سپس روی ایران ON را برای پورت موردنظر بزن.** در ایران مقصد همان فوروارد فعلی HAProxy استفاده می‌شود. برای خاموش‌کردن **اول ایران‌ها، سپس خارج** را OFF کن. تأیید متنی یا Enter اضافه پرسیده نمی‌شود؛ این اسکریپت به سرور دیگر SSH نمی‌زند.

اگر OFF پیام draining داد، اتصال‌های قدیمی هنوز بازند؛ مسیر برگشت آن‌ها حفظ می‌شود. بعد از پایان آن‌ها، OFF را دوباره اجرا کن تا منابع باقی‌مانده پاک شوند. روشن‌کردن دوباره همان پورت در زمان draining پشتیبانی می‌شود.

## همان دستور curl قبلی

فایل‌های این بسته، به‌خصوص `GRETUN.sh` و `transparent_forward.py` را با هم در ریشه مخزن GitHub جایگزین کن. این بسته خودش مخزن را منتشر یا تغییر نمی‌دهد. بعد از انتشار، دستور همیشگی نسخه جدید را دریافت می‌کند:

```bash
bash <(curl -Ls --ipv4 https://raw.githubusercontent.com/0fariid0/GRE-TUN/refs/heads/main/GRETUN.sh)
```

گزینه ۹ منوی اصلی، فایل کمکی را خودکار دریافت می‌کند؛ SHA256 آن باید با همین نسخه مدیر تطبیق داشته باشد. دانلود ناموفق یا فایل ناسازگار جایگزین فایل قبلی نمی‌شود. ورودی مستقیم منوی اصلی روی خارج به نصب HAProxy نیاز ندارد.

## تغییرات این نسخه

- روشن‌کردن روی پورت اصلی، بدون listener آزمایشی و بدون تغییر پورت کلاینت.
- اتصال backend شفاف HAProxy به رابط تونل انتخاب‌شده مقید می‌شود.
- قبل از جابه‌جایی فوروارد اصلی، اتصال TCP با source غیرمحلی روی همان رابط بررسی می‌شود؛ پاسخ `ready` و پینگ به‌تنهایی کافی نیستند.
- شکست این بررسی، فوروارد اصلی را جابه‌جا نمی‌کند. شکست reload نیز تلاش برای برگشت تنظیمات قبلی را اجرا می‌کند.
- تبدیل پروفایل‌های آزمایشی/فعال نسخه قبلی به حالت جدید، بدون listener اضافه؛ پشتیبانی از OFF و ON مجدد در حالت draining.
- سرویس آمادگی خارج باید واقعاً شروع به listen کند تا آماده گزارش شود؛ خطاهای بررسی در journal ثبت می‌شوند.
- گزارش خطای اعمال تنظیمات در `/etc/gretun-transparent/last-error.log` ذخیره می‌شود؛ شامل مسیرها و قوانین مربوط است و کلید WireGuard یا محتوای بسته‌های کاربران را ذخیره نمی‌کند.

## محدوده و نتیجه تست

این بخش برای **IPv4، فوروارد ساده TCP در HAProxy و رابط‌های routed GRE/GRE Plus و WireGuard تک-peer** است. HTTP/UDP، تنظیمات پیچیده HAProxy و WireGuard چند-peer خودکار تبدیل نمی‌شوند. در خارج، AllowedIPs همان peer WireGuard با Table=off برای دریافت source کاربران گسترش می‌یابد؛ جدول اصلی مسیریابی به default روی WireGuard تبدیل نمی‌شود.

۱۰۰ تست خودکار گذشته‌اند. آزمون‌ها شامل مدل‌سازی قوانین و چرخه rollback، نصب و بررسی واقعی loopback سرویس آمادگی هستند. این محیط CAP_NET_ADMIN ندارد؛ آزمون واقعی GRE/WireGuard و handshake کلاینت Xray روی سرورهای شما انجام نشده است. بررسی TCP جدید جای احراز هویت یا handshake برنامه را نمی‌گیرد. علت دقیق قطع قبلی از خروجی بعد از OFF قابل تعیین نبود؛ تضمین بی‌خطا بودن روی همه سرورها داده نمی‌شود.
