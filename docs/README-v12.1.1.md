# GRE-TUN 12.1.0

همان منوی اصلی نسخهٔ 12.0.6، با بازشدن سریع‌تر و یک نوع تانل اختیاری BackPack.

## چه چیزی تغییر کرده؟

- گزینه‌ها، شماره‌ها و متن منوی اصلی عین نسخهٔ قبلی است.
- مراحل ساخت GRE، GRE Plus و WireGuard و تمام توابع HAProxy تغییر نکرده‌اند.
- فقط در انتخاب نوع تانل، گزینهٔ ۴ یعنی **BackPack L3** اضافه شده است.
- BackPack فقط شبکهٔ داخلی می‌سازد؛ فوروارد پورت، پنل وب، ربات، منو، مانیتور و آپدیت خودکار BackPack اجرا نمی‌شوند.
- تانل جدید در جدول‌ها، حذف تکی/چندتایی/همه، ریست همه، پینگ، تست سرعت، لاگ و انتخاب مقصد HAProxy شناخته می‌شود.
- تنظیمات موتور `ports = []` دارد. `accept_udp = false` فقط فوروارد داخلی را خاموش می‌کند؛ خود شبکهٔ لایهٔ ۳ همچنان TCP، UDP و ICMP حمل می‌کند.
- رنج مستقل: `10.40.ID.1/30` ایران و `10.40.ID.2/30` خارج، اینترفیس `bptunID`.
- فایل‌های قبلی GRE، GRE Plus، WireGuard و HAProxy به قالب دیگری تبدیل نمی‌شوند.

## علت دیر بازشدن و اجرای سریع

نسخهٔ قبلی قبل از نمایش منو، `bootstrap_runtime_repairs` را همگام اجرا می‌کرد: نصب مجدد نسخهٔ اسکریپت، بازنویسی سرویس‌ها و تایمرها، daemon-reload، اعمال sysctl، بررسی و تعمیر تانل‌ها و آماده‌سازی سرویس UDP. اجرای `bash <(curl ...)` ممکن بود به دانلود دوم اسکریپت هم منجر شود.

در این نسخه بازکردن و خروج از منو، این عملیات را اجرا نمی‌کند. آماده‌سازی قدیمی در اولین عملیات مدیریتی تغییر‌دهندهٔ همان نشست انجام می‌شود؛ بنابراین ممکن است آن عملیات هنوز کمی زمان ببرد. سرویس‌های موجود بدون بازکردن منو کار خود را ادامه می‌دهند. چیزی در پس‌زمینهٔ منو شروع نمی‌شود که با انتخاب‌های کاربر مسابقه داشته باشد.

**دانلود اولیهٔ دستور `curl` خارج از اسکریپت است و به شبکه بستگی دارد. برای بازشدن سریع، نسخهٔ محلی را اجرا کنید.**

### نصب از همین بسته (پیشنهادی)

روی هر دو سرور پوشهٔ `GRE-TUN` را قرار دهید، داخل آن اجرا کنید:

```bash
sudo bash install-local.sh
```

این نصب، اسکریپت و آرشیو موتور را محلی نگه می‌دارد و تانل‌های در حال اجرا را ریست نمی‌کند. بعد از آن همیشه برای بازکردن منو:

```bash
sudo bash /usr/local/bin/gretun-manager.sh
```

یا بدون نصب محلی، داخل پوشهٔ بسته:

```bash
sudo bash GRETUN.sh
```

### آپلود به GitHub خودتان

**محتویات داخل پوشهٔ `GRE-TUN`** را در ریشهٔ مخزن `0fariid0/GRE-TUN` قرار دهید؛ یک پوشهٔ تو‌در‌توی اضافی نسازید. فقط فایل ZIP را در مخزن قرار ندهید.

ساختار مهم:

پس از جایگزینی فایل‌ها، دستور قبلی همچنان معتبر است:

```bash

```

موتور تنها هنگام ساخت BackPack لازم می‌شود. اول کنار اسکریپت یا در کش نصب محلی جست‌وجو می‌شود؛ در نبود آن، از `engines/backpack` در **مخزن خودتان** دریافت می‌شود. دانلود موتور هنگام بازکردن منو یا کار با GRE/WireGuard انجام نمی‌شود. نسخه و SHA-256 موتور در اسکریپت ثابت است و فایل نامعتبر نصب نمی‌شود.

## ساخت BackPack بدون تغییر روش فوروارد

### ایران

1. منوی اصلی **۱ ـ create/update tunnel**.
2. نوع تانل **۴ ـ BackPack L3**.
3. نقش **۱ ـ Iran**.
4. شمارهٔ تانل (مثلاً `1`)، IP محلی و IP عمومی خارج.
5. روش انتقال: `UDP`، `QUIC`، `PCK` یا `xDi/ICMP`.
6. پورت تانل؛ برای شمارهٔ ۱ پیش‌فرض `52001` است. برای xDi این عدد شناسهٔ ICMP است.
7. توکن: Enter یک توکن تصادفی ۶۴ رقمی هگز می‌سازد. آن را برای سرور خارج نگه دارید.
8. MTU: پیش‌فرض `1380`؛ تنظیم خودکار MTU فعال است.
9. تأیید ساخت.

### خارج

همان منوی **۱ ← نوع ۴** را باز کنید، نقش **۲ ـ Kharej** را بزنید. همان شماره، روش انتقال، پورت و MTU ایران را وارد کنید؛ IP مقابل این بار IP ایران است. **همان توکن ایران** را وارد کنید. خارج توکن دیگری تولید نمی‌کند.

برای شمارهٔ ۱:

- ایران: `bptun1` با IP `10.40.1.1`، مقصد `10.40.1.2`.
- خارج: `bptun1` با IP `10.40.1.2`، مقصد `10.40.1.1`.

سمت ایران به خارج اتصال می‌زند. آی‌پی محلی انتخاب‌شده روی ایران باید همان source مسیر به خارج باشد؛ اسکریپت ناسازگاری را رد می‌کند. خارج باید روی IP واقعاً تخصیص‌یافته به سرورش گوش بدهد. این راه‌انداز برای دو سرور با IPv4 قابل‌دسترسی طراحی شده؛ تنظیم خودکار NAT یا domain endpoint ندارد.

بعد از ساخت **هر دو سمت** از گزینهٔ **۴ ـ ping test tunnels** ارتباط را بررسی کنید. `active` یعنی سرویس و اینترفیس محلی فعال‌اند؛ به‌تنهایی به معنی تأیید ارتباط دوطرفه نیست. QUIC ایران ممکن است تا آماده‌شدن خارج، `pending` باشد؛ فایل‌ها نگه داشته می‌شوند و موتور تلاش می‌کند. ادامهٔ این وضعیت بعد از راه‌اندازی خارج نیازمند بررسی لاگ است.

### فوروارد مثل قبل

روی ایران همان گزینهٔ **۶ ـ haproxy port manager** را باز کنید و هنگام انتخاب مقصد، ردیف BackPack یا IP داخلی خارج (مثلاً `10.40.1.2`) را انتخاب کنید. ساخت/ویرایش پورت‌ها، HAProxy TCP و قواعد UDP همان کد قبلی هستند. پورت موتور با پورت سرویس مشتری فرق دارد؛ پورت موتور را برای فوروارد مشتری انتخاب نکنید.

تست سرعت نیز همان گزینهٔ **۵** است: سرور خارج باز می‌ماند و ایران یک، چند یا همهٔ ردیف‌ها را انتخاب می‌کند. تانل BackPack هم در همین فهرست می‌آید.

## ایمنی تغییر تنظیمات و سرویس‌ها

- تنظیمات موتور قبل از اعمال با دستور رسمی `backpack check` بررسی می‌شود.
- فایل‌های توکن/کانفیگ با مجوز `600` در پوشهٔ `700` ذخیره می‌شوند.
- شکست اعمال تنظیمات، فایل‌های قبلی و وضعیت فعال/غیرفعال قبلی سرویس را برمی‌گرداند.
- هر تانل سرویس مستقل `gretun-backpack@ID.service` دارد.
- موتور در صورت خروج ناموفق توسط systemd دوباره شروع می‌شود؛ افت پینگ به‌تنهایی باعث ریست آن نمی‌شود.
- قواعد اتصال موتور با کامنت مخصوص همان شماره ثبت و حذف می‌شوند؛ جدول NAT یا قوانین بقیه پاک نمی‌شود.
- تایمر سلامت موجود، قواعد اتصال موتورهای در حال اجرا را در صورت حذف‌شدن دوباره برقرار می‌کند؛ سرویس متوقف‌شدهٔ دستی را راه نمی‌اندازد.
- عملیات ساخت/ویرایش و حذف BackPack قفل مشترک دارند.
- ویرایش یک سمت، تنظیمات سمت دیگر را خودکار عوض نمی‌کند؛ پارامترهای مشترک باید در هر دو طرف یکی باشند.

کانفیگ: `/etc/gretun-backpack/tunnel-ID.toml`

لاگ از همان منوی اصلی گزینهٔ **۷** قابل‌دیدن است؛ یا:

```bash
sudo journalctl -u gretun-backpack@1.service -n 60 --no-pager
```

## روش‌های انتقال این نسخه

چهار روش L3 یعنی UDP، QUIC، PCK و xDi اضافه شده‌اند. TCP stream، WebSocket و KCP به این انتخاب‌ها اضافه نشده‌اند چون حالت شبکهٔ داخلی L3 این موتور آن‌ها را نمی‌پذیرد. حالت‌های spoof/SNI، پنل و ابزارهای مستقل BackPack در این رابط عرضه نمی‌شوند.

موتور اصلی بدون تغییر، نسخهٔ `v1.8.5` است؛ برای Linux amd64 و arm64 داخل بسته قرار دارد. استفاده از یک نسخهٔ موتور در هر دو سمت لازم است. فایل‌های سورس و مجوز همراه بسته‌اند.

## بررسی‌ها و محدودیت‌ها

گزارش دقیق در `docs/VALIDATION.md` است. آزمون‌های اسکریپت، منوی بدون عملیات شبکه، نصب آفلاین و بررسی چک‌سام، تأیید واقعی کانفیگ با موتور، اتصال به فهرست HAProxy و بازگردانی خطا اجرا شده‌اند. ارتباط واقعی ایران/خارج، ظرفیت تحت بار و فایروال ارائه‌دهنده در این محیط آزمایش نشده است؛ برای این موارد از پینگ و تست سرعت روی سرورها استفاده کنید.

سابقهٔ نسخهٔ 12.0.6 در `docs/README-v12.0.6.md` حفظ شده است.
